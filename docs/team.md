# 成员页：创始团队和核心成员

/people 上出现的人都在 Supabase 的 `team_members` 表里，一人一行。运营在后台的 Table editor 里改，不用发版，改完一分钟左右页面就更新。数据库结构见迁移 `20261026020000_team_members.sql`。

## 规矩

- **只放同意的人。** 每个人都要明确同意：照片、展示名和成员卡会公开放在官网上，官网会被搜索引擎收录，随时可以要求撤下。同意的时间填进 `consent_at`。没同意的人不加行。
- **名字由本人决定。** `display_name` 填本人选的展示名，昵称、英文名、真名都行，最多 20 个字。
- **照片文件名不用真名。** 用下面的脚本生成随机文件名。
- 同意列名、但不想放照片的人：行照常加，照片两列留空，页面上用吉祥物代替。

## 收集

一个表单，每人填：

- 展示名
- 部门和职位（创始人不用填职位）
- 一句话介绍，中文一句、英文一句，都可以不填
- 个人链接（选填，`https://` 开头）
- 头像：正方形，脸在中间，至少 800×800（必交）
- 竖版个人照：4:5，至少 1200×1500（创始人必交，核心成员选填）
- 官网成员账号的邮箱（如果已经在官网领了卡）
- 必勾：「同意照片、名字和成员卡公开放在 BuilderSpace 官网上；官网会被搜索引擎收录；可以随时要求撤下。」

交原图（JPG 或 PNG），不要从微信转发，微信会压缩。iPhone 的 HEIC 先导出成 JPG。

## 处理照片

```bash
node scripts/team-photos.mjs --out team-photos-out 原图1.jpg 原图2.jpg …
```

脚本会：按照片里的方向转正，删掉所有元数据（包括 GPS 位置），自动对准脸裁成 800×800 的头像和 1200×1500 的竖版照，转成 WebP，用随机文件名保存，最后打一张对照图 `contact-sheet.jpg`。表格里列出每张原图对应的两个文件名。

先看一眼对照图。裁歪了的，把原图手动裁一下再跑一次。原图比要求小时脚本会提醒，最好让本人重新发原图。

`team-photos-out/` 已经加进 `.gitignore`，不会被提交。处理完删掉。

## 上传和填表

1. Supabase 后台 → Storage → `team-photos`，把 `.webp` 文件拖进去（放在根目录，不要建文件夹）。
2. Table editor → `team_members` → Insert row：

| 列                              | 填什么                                                                                                                                                                                                                                                 |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `display_name`                  | 展示名                                                                                                                                                                                                                                                 |
| `team`                          | `founder` / `ops` / `tech` / `events`                                                                                                                                                                                                                  |
| `position`                      | 创始人留空。运营部：`content` 内容与渠道、`design_media` 设计与影像、`recruiting` 招募与成员发展。技术部：`product` 产品与项目、`web_tools` 网站与工具、`teaching` 教学与支持、`tech_explore` 技术探索。活动部：`events` 活动、`partnerships` 对外合作 |
| `title`                         | 创始人填 `Co-President`，核心成员一般留空                                                                                                                                                                                                              |
| `bio` / `bio_en`                | 一句话介绍，中文最多 80 字，英文最多 240 个字符；英文没有就留空，英文页面显示中文                                                                                                                                                                      |
| `link_url`                      | 个人链接，`https://` 开头                                                                                                                                                                                                                              |
| `avatar_path` / `portrait_path` | 脚本输出的文件名，比如 `017c994f76eb-sq.webp`                                                                                                                                                                                                          |
| `member_id`                     | 本人在官网的成员账号：Authentication → Users 里按邮箱找到这个人的 User UID 填进来。填了以后页面显示本人设计的成员卡和真实编号；不填就是默认卡面                                                                                                        |
| `spark`                         | 没照片也没关联账号时用哪只吉祥物占位：`vivi` / `lumi` / `geo` / `momo` / `kiko`                                                                                                                                                                        |
| `sort`                          | 同一部门里的顺序，小的在前                                                                                                                                                                                                                             |
| `slug`                          | 只给有个人介绍页的人填，比如 `evan`，地址就是 `/people/evan`。介绍页正文在 `src/lib/founder-profiles.ts`，按 slug 对应；不填的人卡片点不开                                                                                                             |
| `consent_at`                    | 本人同意的时间                                                                                                                                                                                                                                         |
| `listed`                        | 默认 `true`                                                                                                                                                                                                                                            |

填错了数据库会拒绝，比如运营部填了技术部的职位、文件名带空格或大写。

## 撤下一个人

1. `team_members` 里把这个人的 `listed` 改成 `false`（或者整行删掉）。
2. Storage → `team-photos` 里删掉这个人的两张照片。

页面一分钟左右就看不到了。已经被搜索引擎收录的图片，要等搜索引擎下次抓取才会消失。

## 页面上怎么显示

- 创始人在上面，一排三张竖版大照片，按 `sort` 排（Evan 在中间）。点照片进入 `/people/<slug>` 个人介绍页，照片从卡片移过去。介绍页的经历、奖项、个人网站写在 `src/lib/founder-profiles.ts`，改这些文字要发版。
- 核心成员按运营 / 技术 / 活动分三行，每人显示自己设计的成员卡，下面是小头像和职位。点卡片会放大，能翻到背面、左右换人。地址会变成 `/people?m=…`，可以直接把某个人的卡发出去。
- 一个部门超过 5 个人就分页，每 6 秒自动翻一页，鼠标放上去会停。
- 照片都是原色。
